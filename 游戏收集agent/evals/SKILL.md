# 游戏判断修改实验

修改标准前读取本目录 README.md 和原有金标准。先定位问题属于事实证据、Skill 分析方法还是用户口味；模型分歧不等于用户偏好改变。不要通过移动推荐分数或复制测试答案来修复问题。

正式 Taste、来源 Skill 和原测试集维持原状。将小范围修改写入候选文件；记录可被反驳的假设、预期收益和可能受损的偏好。当前正式文件可能有未提交修改，因此基线取当前工作区并保存全文与哈希，不能默认为 HEAD。

用 eval.py prepare 固定同一组输入、标准全文、金标准、模型和重复编号。正式benchmark当前仅使用原有33个获审案例，不自动加入假想或其他新增案例。旧扩充提案已归档停用；即使归档案例标为approved，prepare也不会载入。用户明确要求查看假想测试结果时，可用diagnose单独运行辅助诊断；这不是批准测试扩充，不能改案例审核状态、并入正式指标或称为盲测保留集。改动前已有真实输出可导入，只要标准和输入与快照一致。

分别启动独立 Agent（默认 gpt-6-luna，fork_turns=none），仅给各自 bundle 的 request.md、inputs.json、taste.txt、SKILL.md。不得给金标准、预期答案、假设、旧输出、其他版本或历史报告。读取并执行 request.md。测试封装禁止联网及正式数据写入；事实核验应在输入冻结前完成。不要让主 Agent 代写结果，也不要把静态检查称作行为测试。若没有模型调用能力，只交付可执行流程并明确未运行。

导入实际结果后运行 compare。推荐覆盖是主指标：金标准“推荐”和“必须推荐”共同表示应该推荐，判为“不推荐”才是严重漏推荐。两种正向强度之间浮动只作次要记录，不自动算退化，也不要求逐字匹配用户当时的主观优先级。“信息不足”单列待确认，既不冒充推荐覆盖，也不等同于明确拒绝。金标准“不推荐”被推荐作为误推荐单列，仍需审查是否有证据支持新价值。五分制记录不自动裁定判断质量。审阅具体活动、体验中心、结构差异、叙事作用、证据边界以及个人兴趣与研究价值的区分。同分也可能改进；只添加术语而没有具体因果依据不算改进。独立模型审阅可辅助，关键案例与正式采用留给人工；模型意见不得填入 human-review.json 冒充人类。

开发集出现问题时，先读原始判断和证据，提出最小修正；冻结新实验重测，不覆盖旧记录。把退化、持平和不确定都保留。发现基线与候选同时失败，不应称作“候选通过”。必要时对关键案例用新实验重复，记录所有运行，不挑最好的一次。

开发完成后才打开已审核保留集；一旦看到结果并继续调参，该保留集已被消耗，下轮需要新样本。已有33个案例曾参与调参，全部是开发/回归集；不能重新改名当保留集。当前不扩充测试集，没有独立保留样本；不能证明泛化能力，也不为获得保留集而自行引入假想案例。

判断依据虚构、错误理解或丢失个人偏好仍可能构成语义退化，但必须指出具体问题，不能只凭5分变4分或必须推荐变推荐。独立模型审阅也必须使用上述严重程度口径。

给用户的采用建议需说明实际改善、严重退化、证据限制与未解决问题。只有出现具体且可信的改善证据才考虑增加规则；收益不明显就保留原标准，避免无谓复杂，不因候选写得更详细而采用。替换正式标准遵循用户已给出的授权范围；用户已授权依证据决定时，不重复索取同一授权。测试集新增仍须用户审核，工具不自动替换任何正式文件。
